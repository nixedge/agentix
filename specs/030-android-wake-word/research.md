# Research: Hey Agentix

Consulted 2026-11-01. Android and sherpa sources are absent from agentic-nix inventory, and its fetcher does not support Android sources; official upstream source/docs inspected directly.

Android framework `VoiceInteractionService.createHotwordDetector` and current always-on detector implementations are SystemApi/require MANAGE_HOTWORD_DETECTION. Default selection does not supply a reusable Google wake-word model. Do not reflect hidden APIs or claim DSP integration: [AOSP implementation](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/service/voice/VoiceInteractionService.java), [SoundTrigger overview](https://source.android.com/docs/core/audio/sound-trigger).

Use explicitly enabled software keyword spotting instead of looping SpeechRecognizer. sherpa supports arbitrary BPE keywords without training, Android JNI and explicit native cleanup. Pin2.0.1 and model release2024-01-01, licenseApache-2.0. Runtime AAR API inspected with JDK javap; source signatures/cleanup verified: [KeywordSpotter](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.1/sherpa-onnx/kotlin-api/KeywordSpotter.kt), [OnlineStream](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.1/sherpa-onnx/kotlin-api/OnlineStream.kt), [keyword format](https://k2-fsa.github.io/sherpa/onnx/kws/index.html). Engine/model suitability for owner's voice remains a phone test, not inferred from repository support.

Start microphone FGS only from explicit visible UI, require microphone and notification access, no sticky/boot restarts. Background microphone service and background activity launches have separate restrictions; use active default VoiceInteractionService.showSession and existing startAssistantActivity rather than general FGS startActivity: [FGS restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [voice service](https://developer.android.com/reference/android/service/voice/VoiceInteractionService). Persist preference separately from runtime state; no assertion of always-on availability after OS kill.

SentencePiece0.2.1 with the model's bpe.model encodes `HEY AGENTIX` as `▁HE Y ▁A G ENT I X`. Native2.0.1 Linux fixture runs verified model loading and known LIGHT UP detection. Initial keyword boost1.5/threshold0.35 missed eSpeak's synthetic Hey Agentix; threshold reduction alone also missed it. Boost3/threshold0.25/two trailing blanks detected the synthetic phrase, with no wake result for synthetic Hey Google/Hey assistant/Hey agent and two upstream ordinary-speech WAVs. Those exact settings and cases are pinned in `checks.x86_64-linux.agentix-wake-model`. This is synthetic/Linux evidence, not phone accuracy or false-trigger-rate evidence. A15-second stream rotation bounds retained features/history; microphone buffers stay1600samples, one inference thread. Worker uses a ten-minute wake-lock timeout renewed every five minutes, released on pause/exit. No audio writes or network calls in the detector.

The Android AAR reports ONNX Runtime1.28.2. Apache2 sherpa/model licensing plus matching ONNX Runtime MIT/third-party notices are packaged under app assets/licenses. All native ABIs are supplied by the pinned upstream AAR; physical Pixel loading remains an acceptance checkpoint.

Native-library APKs need16KiB ZIP alignment as well as ELF segment alignment for16KiB devices. Update downstream signing from deprecated zipalign `-p` (4KiB) to `-P16`, and verify alignment after signing as well as the signature. Inspected arm64 sherpa/ONNX LOAD segments report0x4000 alignment. Primary references: [zipalign](https://developer.android.com/tools/zipalign), [page sizes](https://developer.android.com/guide/practices/page-sizes).
