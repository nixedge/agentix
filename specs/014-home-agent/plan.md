# Implementation Plan: agentix-agent Home Assistant

**Branch**: `014-home-agent` | **Date**: 2026-08-19 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/014-home-agent/spec.md`

## Summary

Build `agentix-agent` — a new Rust binary crate in the agentix workspace that runs as a persistent home-assistant daemon. It exposes a mobile-friendly HTTP chat interface, manages a SQLite-backed household todo list, integrates with Google Calendar and Gmail via REST + OAuth2, sends push notifications via ntfy.sh, and uses the existing `agentix-harness` agent loop for all LLM reasoning. Voice input from the phone is transcribed by proxying audio to the existing `agentix-daemon` whisper endpoint. The ESP32 voice interface is designed for via a reserved HTTP endpoint but not implemented.

## Technical Context

**Language/Version**: Rust edition 2021, stable (1.80+ via fenix in Nix)
**Primary Dependencies**:
- `agentix-harness` (agent loop, Tool trait)
- `axum 0.8` (HTTP server, multipart)
- `sled 0.34` (embedded key-value store)
- `yup-oauth2 12.x` (Google device-flow OAuth2)
- `reqwest 0.12` (ntfy.sh, Google REST API calls)
- `chrono 0.4`, `uuid 1.x`, `toml 0.8`

**Storage**: sled embedded key-value store (todos, notifications, Gmail cursor, conversation sessions); PostgreSQL not required
**Testing**: `cargo test -p agentix-agent`; integration tests use a `tempfile::TempDir`-backed sled db
**Target Platform**: Linux server (home LAN); NixOS module for service management
**Project Type**: Binary crate (daemon + CLI subcommands)
**Performance Goals**: Notification delivery within 5 minutes of trigger; chat round-trip under 30s on LAN
**Constraints**: No internet-exposed port (LAN/VPN only); C++ deps (whisper, llama) must not be pulled into this crate; no blocking calls on tokio runtime
**Scale/Scope**: Single user (Samuel); tens of todos; daily Gmail/calendar scans

**Structure Decision**: Single binary crate. No separate library sub-crate needed — the public API surface is the HTTP/CLI interface, not a Rust library. Agent tools, store, and Google wrappers are internal modules.

Workspace `Cargo.toml` gains `"agentix-agent"` in `members`. `flake.nix` gains `agentix-agent` package attribute and NixOS service module.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Principle I: agentix-agent binds its own port (not agentix-daemon) | The home agent is a distinct user-facing service with an incompatible operational lifecycle: it runs persistent background schedulers (Gmail polling, notification delivery) that must survive independently of the inference gateway, and it serves a mobile web UI on a separate port with its own session state and config. | Extending agentix-daemon would merge two operationally independent services: the inference gateway would carry Gmail/calendar credentials, scheduler tasks, and a mobile UI — all unrelated to its core concern. Restart of one would restart the other; config, secrets, and startup order would become entangled. The daemon must stay focused on LLM inference. |
| Principle IV: agentix-agent runs without bubblewrap jail | agentix-agent holds the Google OAuth token cache and ntfy topic secret; bubblewrapping would prevent access to these credentials (per the constitution's stated goal: "eliminating credentials from the jail filesystem") | No viable path to run an OAuth2 client inside a bubblewrap jail that cannot access its credential file; service-account alternative requires sharing the personal calendar with a service account, which is a larger credential surface |

## Implementation Phases

### Phase A — Scaffold and Storage (P1 foundation)

**Goal**: Binary compiles and starts; SQLite migrations run; CLI subcommands (`todos list`, `todos add`, `todos done`) work; `GET /health` returns ok.

Tasks:
1. Add `agentix-agent` to workspace `Cargo.toml` and `flake.nix` (basic package attribute; full NixOS service module deferred to Phase G)
2. Write `Cargo.toml` with all dependencies
3. Write 4 SQLite migrations
4. Implement `config.rs` (toml loading, path expansion, env override)
5. Implement `db.rs` (pool setup, migration runner)
6. Implement `store/todos.rs` (insert, list, complete, update, dedup)
7. Implement `main.rs` CLI skeleton (clap: `daemon`, `todos {list,add,done}`)
8. Implement `GET /health` endpoint
9. Unit tests: TodoStore with `:memory:` SQLite

### Phase B — Notifications and ntfy (P1 delivery)

**Goal**: Notification scheduler runs; ntfy.sh POST works; overdue todos trigger a phone notification.

Tasks:
1. Implement `tools/ntfy.rs` (NtfyTool → reqwest POST with title/body/priority headers)
2. Implement `store/notifications.rs` (dedup check, record sent/failed)
3. Implement `scheduler/notification.rs` (tokio interval: query overdue todos → ntfy)
4. Implement `agentix-agent notify test` CLI subcommand
5. Integration test: mock ntfy endpoint; verify notification sent exactly once per overdue todo

### Phase C — HTTP Chat Interface (P2)

**Goal**: Phone browser can open the web UI, send a text message, receive an agent reply. Session context persists across turns.

Tasks:
1. Implement `static/index.html` (mobile-first, text input, chat history, voice record button)
2. Implement `store/sessions.rs` (load/save message JSON, prune old sessions)
3. Implement `http/chat.rs` POST /chat (session cookie, AgentLoop with TodoTool, NtfyTool)
4. Wire todo and ntfy tools into the agent loop
5. Implement `GET /` to serve embedded HTML
6. Integration test: POST /chat with fake agent, verify session cookie and reply

### Phase D — Voice Input (P2 completion)

**Goal**: Phone microphone button works; audio upload transcribes via daemon; transcription processed as chat.

Tasks:
1. Implement `http/chat.rs` POST /chat/voice (multipart → stream to daemon `/v1/audio/transcriptions`)
2. Add MediaRecorder JS to `index.html` (WebM/Opus + MP4/AAC fallback detection)
3. Handle empty transcription with user-facing error message
4. Integrate audio upload test (mock daemon transcription endpoint)

### Phase E — Google Calendar Integration (P3)

**Goal**: `calendar_list_events` and `calendar_create_event` tools work; agent can answer "what's on my plate this week?"

Tasks:
1. Implement `google/auth.rs` (yup-oauth2 device flow, token cache load/save)
2. Implement `google/calendar.rs` (list events REST call, create event REST call)
3. Implement `tools/calendar.rs` (CalendarTool implementing both tools)
4. Wire CalendarTool into AgentLoop in daemon mode
5. Implement `agentix-agent calendar today` CLI
6. Add notification scheduler: upcoming event reminders (configurable lead time)
7. Integration test with recorded HTTP fixtures (no live Google auth needed)

### Phase F — Gmail Integration (P4)

**Goal**: Background Gmail scan creates todos from actionable emails; deduplication prevents repeat entries.

Tasks:
1. Implement `google/gmail.rs` (list unread, get message metadata + snippet)
2. Implement `store/gmail_cursor.rs` (history_id persistence)
3. Implement `scheduler/gmail_scan.rs` (interval task: list unread → agent reasoning → create todos)
4. Implement `tools/gmail.rs` (GmailTool for on-demand inbox check from chat)
5. Deduplication: check `source_id` before inserting Gmail-derived todo
6. Integration test with recorded Gmail API fixtures

### Phase G — Nix and Polish

**Goal**: `nix build .#agentix-agent` succeeds; NixOS service module works; all code quality gates pass.

Tasks:
1. Add `agentix-agent` package to `flake.nix` (crane buildPackage)
2. Add NixOS module `services.agentix-agent` (enable, configFile, user, group)
3. Ensure all clippy lints pass (`unwrap_used`, `expect_used` handled)
4. Run `cargo fmt --check` and `cargo clippy -- -D warnings`
5. Add `agentix-agent` to CI matrix
6. Update `ARCHITECTURE.md` with new crate and port-binding justification
