# Requirements review

- [x] Name, native Kotlin choice, Nix builds, and future assistant scope reflect the user's request.
- [x] Recorder-specific code is isolated from assistant UI and endpoint configuration.
- [x] Acceptance scenarios distinguish local automation from physical-device evidence.
- [x] Unknown firmware, binding changes, and data loss are explicit constraints.
- [x] No invented backend API or working synchronization is promised by the foundation.
- [x] Scope and measurable build/discovery/configuration criteria are defined.
- [x] Android assistant extension separates default-role invocation from unverified wake-word support.
- [x] Local recognition/TTS, missing language support, cancellation, microphone contention, and backend-not-connected behavior have explicit acceptance scenarios.
- [x] No backend implementation, invented API, cloud key, or root/system execution claim is part of the Android increment.
