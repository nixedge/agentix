The workspace-tests shell supplies the complete CPU build toolchain and fixtures
without requiring the packaged agent launcher to be built before tests start.

## Target GPU run

The fixture uses GPU-compatible 64-wide head/hidden/expert dimensions. Run its
explicit CUDA-versus-CPU check inside a GPU-enabled jail:

```bash
AGENTIX_QWEN_GPU_TEST_BACKEND=cuda nix develop .#qwen --command cargo test \
  -p agentix-qwen --test engine gpu_fixture_matches_cpu_prefill_decode_and_reset \
  -- --ignored --nocapture
```

It checks short and batched prefill, decode and reset with exact greedy token
agreement and quantization-tolerant logit comparisons. Ordinary workspace tests
leave this hardware-dependent test ignored.

Physical validation on the available RTX 5090 Laptop GPU is recorded in
[the 2026-11-12 results](results/2026-11-12/summary.md). The earlier RTX 3090 target
is a separate deployment; these measurements are not a same-host comparison.

Run on the RTX 3090 host with GPU devices and host driver libraries available.
A jail must explicitly expose the devices/driver; the separate GPU flag work is
specified in `/home/sam/home/agentix/GPU-JAIL-PROMPT.txt`. No SSH access is assumed.
CUDA is selected explicitly and never falls back to another backend. The package
adds Nix CUDA 12 NVRTC and Vulkan loader paths, plus `/run/opengl-driver/lib`.
The upstream cudarc loader explicitly supports loading `.so.12` even with its
CUDA 13 bindings; upstream tests compile kernels with NVRTC 12. Actual RTX 3090
kernel execution remains a hardware gate. On other Linux distributions, expose
the host driver library directory via LD_LIBRARY_PATH; do not substitute a Nix
stub driver for the kernel-matched host driver. Vulkan also needs the host ICD.

For a split GGUF, RustingStrata requires standard split filenames and opens all
shards beside the first. If the old files are named `iq3s-00001.gguf` and
`iq3s-00002.gguf`, create standard-named symlinks in an operator-selected directory
on the host (no copying or model conversion is required):

```bash
# Set MODEL_DIR to the existing directory containing those two files first.
test -n "$MODEL_DIR"
ln -s "$MODEL_DIR/iq3s-00001.gguf" "$MODEL_DIR/model-00001-of-00002.gguf"
ln -s "$MODEL_DIR/iq3s-00002.gguf" "$MODEL_DIR/model-00002-of-00002.gguf"
export FIRST_SHARD="$MODEL_DIR/model-00001-of-00002.gguf"
export SECOND_SHARD="$MODEL_DIR/model-00002-of-00002.gguf"
```

Use existing canonical names directly when present. Both files must be mounted
read-only in a jail. Do not modify mapped model files while the worker runs.

```bash
nix build .#agentix-qwen --out-link result-qwen
export AGENTIX_QWEN_COMPUTE=cuda

# Capture identity before benchmarking. Compare these hashes to trusted expected values.

```

The first generation is marked warmup, followed by three measured runs. Each
record includes full output/token IDs, prompt count, first-token latency,
decode rate, context, engine revision and GPU name. Decode throughput counts
transitions after the first generated token and includes a terminal stop step
when present. This measures the Agentix library path, excluding HTTP framing;
the worker HTTP path needs its own smoke test below. Do not compare fixture CPU
speed or upstream RTX 3060/smaller-model claims to the production baseline.
The prompt above matches feature 021's recorded 128-token load test. Verify the
old deployment's context and resource settings before treating the rates as a
matched comparison; that deployment recorded 4.681 tokens/s median decode.

## Worker and gateway

```bash
nix build .#agentix-qwen-worker --out-link result-qwen-worker
export AGENTIX_QWEN_GGUF_SHARDS="$FIRST_SHARD:$SECOND_SHARD"
# Use the two trusted expected SHA256 values, in matching order; do not just trust a new local hash.
export AGENTIX_QWEN_EXPECTED_SHARD_SHA256='FIRST_TRUSTED_SHA256:SECOND_TRUSTED_SHA256'
export AGENTIX_QWEN_SOCKET="$PWD/qwen.sock"
result-qwen-worker/bin/agentix-qwen-worker
```

From another shell, using that absolute socket path:

```bash
curl --unix-socket /absolute/path/to/qwen.sock http://localhost/health
curl --unix-socket /absolute/path/to/qwen.sock http://localhost/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"Reply with OK."}],"max_tokens":8,"temperature":0}'
curl -N --unix-socket /absolute/path/to/qwen.sock http://localhost/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"Explain a Rust iterator."}],"max_tokens":128,"temperature":0,"stream":true}'
```

Configure the gateway with the same AGENTIX_QWEN_SOCKET and AGENTIX_QWEN_MODEL.
Exact matching model requests route to Qwen; other local models continue to
llama. Worker busy/error status and SSE are passed through unchanged.
The NixOS module exposes `services.agentix.qwen` with required `package`, `shards`
and `expectedShardSha256`; compute defaults to CUDA, context to 4096, device to 0,
prefillChunk to 256 and vramMargin to 512 MiB. `modelDir` defaults to
`/var/lib/agentix/qwen`. Enable it explicitly; no service is deployed by this work.

## Acceptance and limitations

Confirm coherent basic text, a nonstreaming function call and a tool-result
round trip, streaming equality under greedy decoding, disconnect recovery,
busy preservation, and repeated 128-token measurements. Record the real model's
PLE, QSA and recurrent-state behavior; synthetic coverage cannot prove those.
Maintain matched GGUF/tokenizer/context/host settings against the old baseline.

Upstream disables MTP and parallel sequence slots for hyper-connection models.
This worker serializes requests, supports greedy text and nonstreaming function
tools, and explicitly rejects structured-output modes, reasoning output,
multimodal input, nonzero temperature and streaming tool calls. The upstream
library is pinned without source modifications. License and attribution are
installed under `share/doc/agentix-qwen`.
