# Implementation Plan: Grammar Enforcement and Responses API

**Branch**: `013-grammar-responses-api` | **Date**: 2026-08-20 | **Spec**: [spec.md](./spec.md)

## Summary

Add token-level grammar enforcement to `/v1/chat/completions` via `LlamaSampler::grammar()` from `llama-cpp-2` (enabled by the `common` feature), and implement a new `/v1/responses` endpoint that accepts the OpenAI Responses API request format. Grammar enforcement converts `response_format.json_object` to a bundled JSON GBNF and `response_format.json_schema` to a schema-derived GBNF via `llama_cpp_2::json_schema_to_grammar()`. Both APIs share the same enforcement mechanism.

## Implementation Phases

### Phase 1: API Types (agentix-api)

Files: `agentix-api/src/lib.rs`

1. Add `ResponseFormatType` enum with `JsonObject`, `JsonSchema`, `Text`, `Unknown` variants. `Unknown` catches unknown values via `#[serde(other)]`.
2. Add `JsonSchemaSpec` struct: `name: Option<String>`, `schema: serde_json::Value`, `strict: Option<bool>`.
3. Add `ResponseFormat` struct: `format_type: ResponseFormatType` (serialized as `type`), `json_schema: Option<JsonSchemaSpec>`.
4. Add `response_format: Option<ResponseFormat>` to `ChatCompletionRequest`.
5. Add `ResponsesRequest` struct (see data-model.md for full definition).
6. Add `ResponsesResponse`, `ResponseOutputMessage`, `ResponseOutputContent` (see data-model.md).

All new types derive `Debug`, `Clone`, `serde::Serialize`, `serde::Deserialize` as appropriate.

### Phase 2: GrammarConstraint in agentix-infer

Files: `agentix-infer/src/lib.rs`

1. Add `GrammarConstraint` enum: `Gbnf(String)`.
2. Add `grammar: Option<GrammarConstraint>` field to `CompletionRequest`.

### Phase 3: Grammar Enforcement in agentix-llama

Files: `agentix-llama/Cargo.toml`, `agentix-llama/src/lib.rs`

1. Enable `common` feature for `llama-cpp-2` in `Cargo.toml`:
   ```toml
   llama-cpp-2 = { version = "0.1", features = ["common"] }
   ```

2. In `complete_sync()`, modify sampler chain construction:
   - If `req.grammar` is `Some(GrammarConstraint::Gbnf(gbnf))`:
     - Build grammar sampler: `LlamaSampler::grammar(&model, &gbnf, "root")` 
     - Return 500 (mapped to InferError) if grammar init fails
     - Prepend grammar sampler before the top-k/top-p/temp/dist chain
   - If `req.grammar` is `None`: existing chain unchanged

   `LlamaModel` is already available in the inference thread — pass it to `complete_sync()` as it already receives `&LlamaModel`.

### Phase 4: Request Translation in agentix-llama (main.rs)

Files: `agentix-llama/src/main.rs`

Add constant:
```rust
const JSON_GBNF: &str = r#"root   ::= object
value  ::= object | array | string | number | ("true" | "false" | "null")
object ::= "{" (string ":" value ("," string ":" value)*)? "}"
array  ::= "[" (value ("," value)*)? "]"
string ::= "\"" ([^"\\] | "\\" (["\\/bfnrt] | "u" [0-9a-fA-F][0-9a-fA-F][0-9a-fA-F][0-9a-fA-F]))* "\""
number ::= ("-"? ([0-9] | [1-9] [0-9]*)) ("." [0-9]+)? ([eE] [-+]? [0-9]+)?"#;
```

In `chat_completions_handler`:
1. Extract `api_req.response_format` after parsing `ChatCompletionRequest`
2. Convert to `Option<GrammarConstraint>`:
   - `JsonObject` → `Some(GrammarConstraint::Gbnf(JSON_GBNF.to_string()))`
   - `JsonSchema` → call `validate_and_convert_schema(schema)` (see below); return 400 on error
   - `Text` / `Unknown` / absent → `None`
3. Set `req.grammar = grammar_constraint` in `CompletionRequest`

Add helper `fn validate_and_convert_schema(schema: &serde_json::Value) -> Result<GrammarConstraint, String>`:
- Reject if schema contains `$ref` with external URI (check `schema_str.contains("\"$ref\"")` + parse)
- Call `llama_cpp_2::json_schema_to_grammar(&serde_json::to_string(schema)?)` 
- Return `Err(String)` on failure → maps to 400 response

Add `/v1/responses` handler:
1. Parse `ResponsesRequest` from body; return 400 on parse failure
2. Map `input` items to `CompletionMessage`: `developer` → `system`, others unchanged
3. Normalize content: string → use directly; array → concatenate text parts
4. Extract grammar from `text.format` (same logic as `response_format`)
5. Build `CompletionRequest`, run inference via `state.engine`
6. Construct `ResponsesResponse` with generated UUIDs, wrap output text in `ResponseOutputContent::OutputText`
7. Detect refusal heuristically (finish_reason or content starting with refusal markers) → `ResponseOutputContent::Refusal`

### Phase 5: Daemon Forwarding

Files: `agentix-daemon/src/gateway/mod.rs`

Add `/v1/responses` route forwarding to the llama socket, identical to how `/v1/chat/completions` is forwarded:
```rust
.route("/v1/responses", post(responses_proxy_handler))
```
Where `responses_proxy_handler` calls `proxy::forward()` with path `/v1/responses`.

### Phase 6: Tests

**Unit tests** in `agentix-llama/src/main.rs` (or a `tests/` file):
- `json_object_response_format_parses` — parse a request with `json_object`, assert `GrammarConstraint::Gbnf` is produced
- `json_schema_response_format_converts` — parse request with valid schema, assert GBNF contains `root ::=`
- `external_ref_schema_rejected` — schema with `$ref: "http://..."` returns error
- `unknown_response_format_type_no_grammar` — `type: "text"` produces `None` grammar
- `responses_request_developer_maps_to_system` — parse ResponsesRequest, assert role mapping
- `responses_request_string_content_normalizes` — plain string content parsed as text
- `responses_request_array_content_normalizes` — array content concatenated

**Integration tests** in `agentix-llama/tests/` (require fixture model):

## Key Constraints

- **Grammar sampler ordering**: grammar sampler MUST be first in the chain (masks invalid tokens before scoring). Wrong order causes subtly broken output, not a runtime error.
- **GBNF root rule name**: always `"root"` — `LlamaSampler::grammar()` requires the root rule to exist by that name.
- **clippy::unwrap_used / expect_used**: use `?` or explicit `map_err` throughout. Grammar errors from `LlamaSampler::grammar()` return a `GrammarError`; map to `InferError::Backend`.
- **`common` feature side effects**: enabling `common` pulls in the llama.cpp `common/` library which adds build time. This is acceptable; it was always a potential dep.
- **Refusal detection**: `agentix-llama` currently has no explicit refusal signal from the model. For MVP, check if the `FinishReason` is `Stop` and content is empty — or treat all non-empty content as `output_text`. Full refusal detection is out of scope.
