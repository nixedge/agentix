# Design evidence

Benchmark 022 used LanceDB 0.40.0/Lance 13.0.0 and unquantized cosine IVF_HNSW_FLAT. At full 279,812-row scale, m20/construction ef400/query ef100/64 partitions/20 probes reduced vector median from 18.11 to 8.23 ms and hybrid from 23.99 to 14.06 ms on the small evaluated set. This motivates the initial configuration; it is not a production latency guarantee because this implementation fetches payloads and adds operational behavior.

Pinned APIs were verified from Cargo-resolved LanceDB source. merge_insert supports atomic replacement with target-only deletion; table schema metadata records model/dimension/version. Local connection read-consistency interval zero refreshes independent readers. Native FTS and label/scalar indexes support prefilters; unindexed fragments remain queryable. The engine uses server-local files, while laptop clients use Agentix's authenticated HTTP API. The dependency's remote Cargo feature is unrelated to that API: it works around the upstream Error::Http build issue already approved in benchmark 022.

A separate shared storage crate avoids pulling inference/reranking into the indexer. PostgreSQL search SQL is removed rather than emulated; one application-side RRF implementation serves every collection. Metadata uses a local Lance table and the same writer lock. A nonblocking filesystem lock provides an explicit busy result instead of silently racing cross-process writes. File writes prepare all embeddings before atomic replacement; cross-file/collection atomicity is deliberately not claimed.

Migration retains the legacy SQL schema only for source fixtures/history. The new export script performs plain SELECT JSON output in one repeatable-read read-only transaction. A two-pass Rust importer validates before writes and records checksum/counts/model assertion; source model identity cannot be proven from the old schema. Import and deployment are separate: implementation does not contact or modify the live source.
